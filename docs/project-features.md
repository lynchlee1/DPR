# 현재 프로젝트 기능 분류

이 문서는 [`behavior-classification-rules.md`](behavior-classification-rules.md)의 **Layer → Behavior → Responsibility** 순서를 적용해 현재 사진 정리 앱의 구현 동작을 정리한다. 구현되지 않은 동작은 포함하지 않으며, UI의 임시 상태와 진행 표시는 별도의 비즈니스 결과로 보지 않는다.

## 1. 기능 경계

| 작업 | 외부 입력 | 비즈니스 결과 | 게시 경계 |
| --- | --- | --- | --- |
| 사진 분석 | 대상 폴더, 유사도 기준, 시간 간격, 분석 방식 | 유사 사진 그룹, 그룹별 보존 기준 사진과 추천 후보, 사진 메타데이터, 분석 실패 및 통계가 포함된 스캔 결과 | 백엔드가 완성된 결과를 세션에 저장하고 상태를 `complete`로 바꾸는 시점 |
| 사진 정리 | 완료된 스캔 결과, 사용자가 확정한 사진 ID, 그룹 전체 이동 허용 여부 | 실제로 시스템 휴지통으로 이동한 파일과 이동하지 못한 파일의 내역 | 모든 선택 파일의 이동 시도가 끝나고 이동 결과를 API 응답으로 반환하는 시점 |

사용자가 UI에서 사진을 보관 또는 삭제 후보로 표시하는 동작은 사진 정리 작업의 입력을 준비하는 Serving 상태다. 실제 사진 정리 결과는 최종 확인 뒤 파일이 시스템 휴지통으로 이동할 때 생성된다.

## 2. Core

Core는 스캔 결과의 값과 구성, 그리고 실제 휴지통 이동 결과를 소유한다.

### Feature

#### Input Handling

**분석 입력 검증**

- 존재하는 폴더, `0~100` 범위의 유사도 기준, 1초 이상의 시간 간격, `quality` 또는 `latest` 보존 전략만 사진 분석 입력으로 받는다.
- 조건을 만족하지 않는 입력을 처리 시작 전에 거부하며, 이는 정상 입력 규칙에 따른 종료이므로 Shutdown이 아니다.

**지원 사진 탐색**

- 선택한 폴더와 모든 하위 폴더에서 JPEG, PNG, WebP, TIFF, BMP 파일을 재귀적으로 찾고, 경로를 대소문자 구분 없이 정렬해 분석 입력으로 준비한다.
- 지원하지 않는 확장자의 파일은 정상 규칙에 따라 분석 입력에서 제외한다.

**휴지통 이동 입력 검증**

- 완료된 스캔 결과를 이전 작업의 입력으로 읽고, 선택 항목이 비어 있지 않은지와 모든 ID가 해당 결과에 존재하는지를 확인한다.
- 선택 파일이 최초 선택 폴더 내부에 있고 현재 일반 파일로 존재하는지 확인한다.
- `allow_delete_all`이 명시되지 않은 경우 각 그룹에 최소 한 장이 남도록 요구한다. 사용자가 전체 그룹 이동을 명시적으로 확인한 경우에는 모든 사진을 입력으로 받는다.

#### Core Processing

**촬영 시각 결정**

- 각 사진의 촬영 시각을 EXIF 촬영 시각, 파일명에 포함된 시각, 파일 수정 시각 순으로 결정하고 선택된 출처를 스캔 결과에 기록한다.
- 이 순서는 정상 데이터에 적용하는 사전 정의 우선순위이므로 뒤 순서의 값을 사용하더라도 Fallback이 아니다.

**사진 특징 추출**

- EXIF 방향을 반영한 사진에서 원본 크기, 파일 크기, pHash, dHash, aHash, 64구간 색상 히스토그램, 선명도 값을 계산한다.
- 사진의 절대 경로에서 안정적인 사진 ID를 만들고, 파일 수정 시각과 크기가 바뀌지 않은 분석값은 캐시에서 재사용한다.

**시간순 인접 사진 선택**

- 분석된 사진을 촬영 시각, 파일명, 전체 경로 순으로 정렬한다.
- 정렬된 목록에서 바로 이웃한 쌍만 확인하고, 시간 차이가 설정 범위 안인 쌍만 시각적 비교 대상으로 선택한다. 앱 UI가 보내는 시간 범위는 현재 60초다.

**시각적 유사도 계산**

- pHash 50%, dHash 20%, aHash 15%, 색상 히스토그램 15%를 조합해 사진 쌍의 유사도를 `0~100` 점수로 계산한다.
- 설정한 유사도 기준 이상인 인접 쌍만 그룹 연결 관계에 포함한다.

**유사 사진 그룹 구성**

- 기준을 통과한 인접 쌍을 연결 요소로 묶고, 사진이 두 장 이상인 요소만 유사 사진 그룹으로 만든다.
- 시간상 가까워도 시각적 연결이 없는 사진은 같은 그룹에 넣지 않는다. 연결된 쌍이 없을 때 그룹 0개를 반환하는 것도 정상 결과다.

**일반 분석 보존 사진 추천**

- 일반 분석의 Core 결과에서는 해상도 55%, 선명도 25%, 파일 크기 20%를 조합한 품질 점수가 가장 높은 사진을 각 연결 요소의 보존 기준으로 선택한다.
- 기준 사진과의 유사도가 설정 기준 이상인 다른 사진을 추천 후보로 표시한다. UI는 일반 분석 결과를 처음 보여 줄 때 이 후보 표시를 모두 해제해 사용자가 직접 판단하게 한다.

**빠른 분석 보존 사진 추천**

- 빠른 분석에서는 각 연결 요소에서 가장 마지막에 촬영된 사진을 보존 기준으로 선택하고, 나머지 사진을 추천 후보로 표시한다.
- 유사도 기준은 사용자가 조절할 수 있으며 UI 기본값은 96%다.

**스캔 결과 구성**

- 그룹별 사진 목록, 기준 사진, 사진 간 유사도 행렬, 시간 범위, 원본 폴더 수와 최대·최소 연결 유사도를 스캔 결과에 담는다.
- 발견·분석 사진 수, 비교·일치 쌍 수, 그룹·추천 후보 수와 용량, 실행 시간을 통계로 담는다.

**시스템 휴지통 이동**

- 검증을 통과한 선택 파일을 경로순으로 시스템 휴지통에 이동하고, 성공한 경로를 정리 결과에 기록한다.
- 영구 삭제는 수행하지 않는다.

#### Result Validation

없음. 완성된 스캔 결과나 휴지통 이동 결과를 별도로 인증하거나 게시 전 일관성을 검사하는 동작은 구현되어 있지 않다.

### Fallback

#### Input Handling

없음.

#### Core Processing

**분석 실패 사진 제외**

- 개별 사진을 열거나 분석하는 중 예상하지 못한 오류가 발생하면 해당 사진을 그룹 결과에서 제외하고, 경로와 사유를 `failures`에 기록한 뒤 나머지 사진 분석을 계속한다.

**일부 휴지통 이동 실패 허용**

- 선택 파일 하나를 휴지통으로 이동하지 못하면 해당 경로와 사유를 실패 내역에 기록하고, 처리 범위를 남은 파일로 줄여 이동을 계속한다.

#### Result Validation

없음.

### Shutdown

#### Input Handling

없음. 유효하지 않은 분석 또는 정리 입력의 거부는 정상 입력 규칙이므로 Feature로 분류한다.

#### Core Processing

**전체 분석 실패 종료**

- 개별 사진 실패 처리 범위 밖의 예외로 완전한 스캔 결과를 만들 수 없으면 결과를 게시하지 않고 현재 분석 실행을 끝낸다.

#### Result Validation

없음.

## 3. Serving

Serving은 로컬 앱 실행, UI와 API 요청, Core 실행 조정, 진행 및 결과 표시를 소유한다. 스캔 결과와 실제 파일 이동의 비즈니스 값을 직접 만들거나 인증하지 않는다.

### Feature

#### Input Handling

**로컬 앱 실행**

- `run.command`가 Python 가상 환경과 의존성을 준비하고 프런트엔드를 빌드한 뒤 `127.0.0.1:8765`에서 서버를 실행한다.
- 같은 앱이 이미 실행 중이면 상태 API로 이를 확인하고 기존 화면을 연다. 새 서버를 시작하면 기본 브라우저에서 앱 주소를 연다.

**폴더 선택 및 기억**

- macOS에서는 시스템 폴더 선택 창을, 다른 운영체제에서는 Tk 폴더 선택 창을 사용한다. 사용자는 경로 입력란을 직접 수정할 수도 있다.
- 선택한 경로는 브라우저 로컬 저장소에 보관해 다음 화면 진입 시 다시 입력으로 사용하며, 폴더 선택 취소는 변경 없는 정상 결과로 처리한다.

**분석 요청 검증 및 생성**

- API가 폴더, 유사도 기준, 시간 간격, `standard` 또는 `quick` 분석 방식을 요청 스키마로 확인하고 존재하는 폴더만 Core 실행에 전달한다.
- 요청마다 메모리 내 스캔 세션을 만들고 별도 스레드에서 Core 분석을 시작한다.

**세션과 이미지 요청 검증**

- 스캔 상태, 미리보기, 휴지통 이동 요청에서 세션 존재 여부와 분석 완료 여부를 확인한다.
- 미리보기는 현재 스캔 결과에 포함된 사진 ID이며 원본 파일이 존재할 때만 반환한다.

**진행 상태 제공 및 표시**

- 분석 세션을 `queued`, `running`, `complete`, `error` 상태와 `analyzing`, `comparing` 등의 단계로 관리한다.
- UI가 350ms 간격으로 세션을 조회하고 처리 수, 전체 수, 백분율, 현재 단계를 표시한다.

**사진 미리보기 제공**

- 원본의 EXIF 방향을 적용하고 RGB JPEG로 변환해 썸네일은 최대 320px, 큰 미리보기는 최대 1400px로 반환한다.
- 원본 수정 시각을 캐시 키에 포함하고, 응답을 1시간 동안 private 캐시할 수 있게 표시한다. 원본 파일 자체는 브라우저로 직접 노출하지 않는다.

**분석 결과 표시**

- 유사 사진 그룹, 그룹별 후보 수, 사진 촬영 시각·크기·용량·상대 경로, 보존 및 후보 상태를 보여 준다.
- 그룹과 사진을 목록, 수평 카드, 필름 스트립으로 이동하며 확인할 수 있고, 사진이 많은 그룹은 가로 스크롤로 전체 항목을 표시한다.
- 그룹이 없으면 현재 기준에서 유사 사진이 없다는 정상 빈 결과 화면을 표시한다.

**일반 분석 검토 상태 초기화**

- 일반 분석이 완료되면 Core 추천 표시를 UI 복사본에서 모두 해제해 삭제 후보 0건으로 검토를 시작한다.
- 이 동작은 Core의 저장된 스캔 결과를 바꾸지 않고, 이후 사진 정리 요청에 사용할 사용자 선택 상태만 준비한다.

**사진 보관 및 후보 입력**

- 사용자가 사진별 후보 추가·해제, 그룹 전부 보관·전부 후보, 위로 밀어 보관, 아래로 밀어 후보를 선택할 수 있다.
- `1~9`는 현재 그룹에서 해당 순서 한 장만 보관하고, `Shift+S/D`는 선택 사진을 보관/후보로, `Shift+N/A`는 현재 그룹 전체를 보관/후보로 표시한다.
- 왼쪽·오른쪽 화살표로 그룹을 이동하며, `Cmd`, `Control`, `Option` 조합과 입력 컨트롤의 키 입력은 사진 상태 변경에 사용하지 않는다.

**빠른 분석 순차 검토**

- Core가 미리 지정한 마지막 촬영 보존 사진과 나머지 후보를 보여 주고, 다음 두 그룹의 큰 미리보기를 미리 불러온다.
- `여기까지 정리하기`는 첫 그룹부터 현재 그룹까지의 후보만 정리 요청 입력에 포함하고 뒤쪽 미검토 그룹은 남긴다.

**휴지통 이동 확인**

- 선택 사진 수와 예상 용량을 확인 창에 표시하고 사용자가 확정한 뒤에만 Core 이동을 요청한다.
- 한 장도 남지 않는 그룹 수를 별도로 경고하고, 사용자가 계속 진행할 때만 `allow_delete_all`을 전달한다.

**정리 결과 반영**

- 이동된 사진을 현재 UI 결과에서 제거하고 남은 사진을 계속 검토할 수 있게 그룹, 기준 사진, 후보 수와 용량을 다시 표시한다.
- 빠른 분석의 부분 정리에서는 처리가 끝난 앞쪽 그룹을 검토 목록에서 제거하며, 모든 그룹이 끝나면 성공 및 실패 건수를 완료 화면에 표시한다.

**상태 및 정적 화면 제공**

- `/api/health`로 로컬 서버 상태를 제공하고, 빌드된 프런트엔드가 있을 때 같은 서버에서 정적 앱을 제공한다.

#### Core Processing

없음. 후보 선택 UI는 사진 정리 입력을 준비하며, 스캔 결과 생성과 파일 이동은 Core가 수행한다.

#### Result Validation

**API 응답 상태 확인**

- UI가 완료된 HTTP 응답의 성공 상태를 확인한 뒤에만 응답 값을 현재 상호작용 결과로 사용한다.

### Fallback

#### Input Handling

**오류 응답 메시지 대체**

- 실패한 API 응답의 JSON 상세 메시지를 읽지 못하면 일반 오류 메시지로 대체해 사용자에게 표시하고 앱의 나머지 상호작용은 유지한다.

**휴지통 요청 실패 시 화면 복원**

- 파일 이동과 사라지는 미리보기 요청이 충돌하지 않도록 후보 카드를 요청 직전에 임시로 숨긴다.
- 휴지통 API 요청이 실패하면 임시 변경 대신 요청 전 스캔 결과와 선택 사진을 복원해 사용자가 다시 검토할 수 있게 한다.

#### Core Processing

없음.

#### Result Validation

없음.

### Shutdown

#### Input Handling

**사용 중인 포트로 실행 종료**

- 앱 상태 API에는 응답하지 않지만 8765 포트를 다른 프로세스가 사용 중이면 잘못된 서버에 연결하지 않고 실행 스크립트를 종료한다.

**폴더 선택기 실행 실패 종료**

- 비 macOS 환경에서 폴더 선택기를 열 수 없는 예외가 발생하면 해당 요청을 500 오류로 끝내고 오류를 표시한다.

**스캔 실행 실패 보고**

- Core가 완전한 스캔 결과를 만들지 못하면 세션을 `error` 상태로 끝내고 오류 내용을 저장하며, UI는 해당 분석 실행의 결과를 열지 않고 오류를 표시한다.

#### Core Processing

없음.

#### Result Validation

**실패한 API 응답 거부**

- HTTP 성공 상태가 아닌 완료 응답은 현재 UI 상태에 적용하지 않고 해당 요청을 오류로 끝낸다. 가능한 경우 서버가 반환한 상세 사유를 표시한다.
